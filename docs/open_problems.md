# Learning Safe Control for Multi-Robot Systems: 开放问题小结

来源：Garg 等, 2023, *Learning Safe Control for Multi-Robot Systems: Methods, Verification, and Open Challenges*。

这篇综述关注学习型多机器人/多智能体系统（MAS）的安全控制，覆盖 shielding、CBF、safe MARL 和学习控制器验证。作者的核心判断是：现有方法通常只能同时满足其中一部分目标，例如可证明安全、可扩展、计算可行、实际可部署；还没有一种方法能在大规模机器人 MAS 中把这些性质统一起来。

## 1. 安全保证与任务活性难以同时成立

安全控制不只是“不碰撞”，还要完成任务，例如到达目标、避免死锁、保持队形或维持连通性。现有学习方法中，安全约束常常会牺牲活性或性能：shield 会过滤动作，CBF-QP 可能导致保守控制，safe MARL 的约束优化也可能降低任务回报。

开放问题是：如何在部分可观测、分布式决策和多机器人交互场景下，同时给出高安全率或形式化安全保证，以及目标到达、死锁解除等活性保证。

对 GNN-based MAS 尤其重要的一点是，GNN 策略虽然适合表达局部交互和扩展到不同规模，但其安全-活性折中还缺少清晰的可验证机制。

## 2. 分解方式决定可扩展性、保守性和可验证性

把单智能体安全方法扩展到 MAS 时，核心难点是如何分解系统。常见分解包括：

- 按智能体对或小团簇处理碰撞约束；
- 按图结构分解 CBF 或 safety filter；
- 用分布式优化近似集中式 shielding；
- 通过组合式证书把局部安全性质合成为全局保证。

问题在于，不同分解会带来不同程度的保守性。只做 pairwise collision avoidance 可能无法处理三者以上的冲突；完全去中心化的 filter 虽然可扩展，但可能比集中式控制更容易陷入低性能或不可行；组合式验证虽然省数据、可泛化，但对分解假设很敏感。

开放问题是：如何系统地选择分解粒度，使方法在安全、性能、可扩展性、通信需求和验证完备性之间取得可解释的平衡。

## 3. 学习型 MAS 的形式化验证仍然很难扩展

论文强调，学习控制器部署前需要验证，尤其是神经网络策略或神经 CBF 这类难解释模型。但 MAS 验证比单智能体更难：

- 状态维度随智能体数量增长，集中式可达性分析和 Hamilton-Jacobi 方法很快不可 tractable；
- 神经网络验证本身已经很难，现有 NNV 工具难以处理大网络，更难处理 GNN、消息传递网络等 MAS 常用结构；
- 系统拓扑和智能体数量可能在运行时变化，验证结果需要对不同图结构泛化；
- 经验测试也面临高维状态空间覆盖不足的问题。

开放问题是：如何验证图神经网络策略、分布式 CBF、组合式证书或 learned shield，并让验证结果能迁移到不同规模、不同拓扑的 MAS。

## 4. 通信不确定性是 MAS 特有的安全风险

多机器人系统经常依赖邻居观测、消息传递、共识或分布式优化。通信延迟、丢包、噪声、拓扑变化以及恶意消息都可能破坏安全。很多现有安全学习方法默认通信可靠，或者只在特定领域里手工处理通信异常。

开放问题是：如何设计同时具备可扩展性和鲁棒性的控制合成与验证工具，使其能够处理：

- 动态通信图；
- 延迟和丢包；
- 有噪声或不完整观测；
- 非合作或恶意智能体；
- 通信受限条件下的安全证书更新。

这也提示 GNN-based MAS 的研究不能只关注图聚合性能，还要把消息不确定性、邻居缺失和对抗通信纳入安全建模。

## 5. CBF-QP 的可行性和输入约束是现实瓶颈

CBF shielding 常通过 QP 修正学习策略的动作，但真实机器人存在速度、加速度、力矩等输入约束。一旦加入这些约束，CBF-QP 可能不可行，从而无法执行安全修正。

开放问题是：如何在输入受限、模型不精确、多约束冲突和动态环境下保证 CBF-QP 可行；如果不可行，系统应如何降级、重规划或协调多智能体约束优先级。

这个问题对多机器人特别尖锐，因为一个智能体的安全修正可能改变其他智能体的可行域，导致局部可行不等于全局可行。

## 6. 理论安全保证到实践之间存在断层

safe MARL、learned CBF 和 shielding 方法都声称能提供某类安全保证，但这些保证常依赖强假设：

- constrained RL 可能需要初始可行策略和真实 value function；
- learned CBF 只有在被验证为真实 CBF 后才继承理论保证；
- shielding 方法要求用户先构造有效的 shield 或 barrier；
- 训练环境中的安全不一定能转移到真实机器人系统。

开放问题是：如何判断没有完整实践安全保证的学习方法是否适合安全关键 MAS；以及如何建立从仿真、学习证书、形式化验证到真实部署的闭环评估流程。

## 7. 安全方法复杂，工程采用门槛高

论文还指出，许多安全方法虽然理论上更强，但组件更多、实现更复杂、调参更困难，因此实践者仍常使用无约束 MARL 或启发式避障方法。

开放问题是：如何把安全机制做成容易使用、可复现、可诊断的训练和部署框架，让安全不只是论文中的附加模块，而是 MAS 学习控制的默认工程能力。

## 可进一步关注的研究切入点

结合本项目的 GNN-based MAS 背景，可以重点考虑以下方向：

- 面向 GNN policy 的安全验证或反例搜索；
- 图结构 CBF / GCBF 在变规模、变拓扑场景下的泛化保证；
- 通信延迟、丢包、邻居缺失下的鲁棒 safety filter；
- CBF-QP 不可行时的多智能体约束冲突解析；
- 将 ORCA、MPC、CBF 与 learned MARL/GNN policy 结合的 runtime assurance 框架；
- 从仿真安全率走向形式化证书和真实机器人测试的评估协议。
